## 一、踩过的坑与规矩（每条都真机吃过亏）

### 1. 先看原始值，再派生
翻车两次：
- 面板高度不对，我从外部反推了两轮"是哪里多乘了一次"，其实只要打印 `draw_panel` 收到的 `h` 就能一眼看出。
- 停靠站滚轮缩放，我用 `(wParam>>16)&0xFFFF` 算出 delta=0 就下结论"没触发"，其实该先打印原始 `wParam`。

**规矩**：任何"我算出来的中间值不符合预期"时，第一步打印**上游原始值**，不要继续猜推导链。

### 2. 先证明诊断本身能用，再信它的结论
给 `draw_panel` 加日志后看到**零输出**，我据此判断"函数没被调用"，实际是日志插错了分支。
更早还把日志放在环境变量开关后面，环境变量根本没传进去。

**规矩**：加完诊断，先确认它**确实能在正常路径上打出东西**，再拿它当证据。

### 3. 测量前确认二进制是新的（2026-10-30 找到真凶）
**这次的根因**：`overlay/src/main.rs` 的 mtime 比编译产物还旧，cargo 判定"源码没变"，
直接跳过编译、把旧产物硬链回去，还打印 `Finished in 0.16s`。
于是连续好几轮的改动**根本没被编译**，包括"黑边怎么改都不变""高度 208 vs 252"。

规矩：
- 改完源码先 `touch -d "2030-01-01" overlay/src/*.rs`（把 mtime 推到未来）
- 编译**必须看耗时**：`Finished in 0.1x s` 基本等于没编；真编要 1~2 分钟（lto + codegen-units=1）
- 编译后用 `md5sum` 对比新旧产物哈希，哈希变了才算新二进制
- 日志里核对 `dock resize ...` 之类**能被新代码改变的具体数值**

### 3b. 测量前确认二进制是新的（原始记录）
面板高度"534 不对"查了很久，最后发现量的是**旧 exe**。

**规矩**：改完必须 `cargo build` → `cp` → 重启进程，再测。日志里有 `=== start pid=N ===` 可以核对是不是新进程。

### 3c. 日志被多个进程共用
`bin/logs/overlay.log` 是**按 exe 目录**开的，插件拉起的浮层、我手动起的 `--dock` 测试进程
都会写同一个文件，日志会交错。排查时先看 `args=[...]` 那行确认是哪个进程。

### 3d. 浮层进程不能写 `~/.dsh/ai-mouse-assets`
`std::fs::write` 到资产目录返回 **os error 5（拒绝访问）**，而同一个目录用 shell 写是成功的。
浮层能写的只有**自己 exe 所在目录**（日志就在那儿）。
所以跨进程的通信用 `<exeDir>/logs/dock-command.json`，不要用 assetDir。

### 3e. 托盘图标：Shell_NotifyIconW 返回 false + err=5
实测（本机，进程以管理员运行）：
```
tray icon added: false err=5 hwnd=HWND(0xd0716) hicon=HICON(0x1002b) cbsize=976
```
句柄、图标、结构体大小都正确，仍然 ACCESS_DENIED。explorer.exe 以普通级别运行，
我们的进程是管理员（`net session` 通过）。这是**同一家族**的第三个平台怪象：
`CreateWindowExW` 新类返回 null、`GetWindowTextW` 跨进程挂死、现在 `Shell_NotifyIcon` 被拒。

下一步可选：
1. 用一个**非提权**的辅助进程只挂托盘图标（需要 `ShellExecuteW` runas=false 启动）
2. 放弃托盘，改用停靠站/小地图表示"正在运行"（已具备）
3. 继续查：确认窗口是否与 explorer 在同一 window station/desktop

### 3f. 小地图三条（2026-10-30 修）
1. **不可拖动**：重画循环每 200ms 调 `present(..., Some(POINT{MAP_X, MAP_Y}))`，
   把窗口拽回常量位置——拖动其实是生效的，只是立刻被弹回。改用 `MAP_POS` 原子量。
2. **不可交互**：`if !dock { WS_EX_TRANSPARENT }` 把光标和小地图一起设成点击穿透。
   改成 `dock || MAP_MODE` 时才可交互。
3. **看不见内容**：桌面框 `0x2A3542`、窗口块 `0x1D2733` 压在 `0x0B1016` 上几乎无色差。
   改为填 `0x141C26` + 描边 `0x4A637D`，窗口块 `0x2E4159` + 描边 `0x3F5672`。

**遗留**：`--map` 进程有自己的 St，没人给它喂光标位置，所以蓝点永远在左上角。
要么让插件周期性 `move`，要么在小地图里读全局光标（`GetCursorPos` 更简单）。

### 4. `compose()` 只能产出画布自己的宽度
```rust
let stride_big = self.w * self.ss;   // 绑死画布尺寸
let i = (row + (ox*ss+sx)*4);        // 按索引取样 = 裁剪，不是缩放
let o = ((oy*self.w + ox)*4);        // 写出步长仍是 self.w
```
`w/h` 只是循环边界。传一个不同的宽度进去 = 越界写 → **空白**。
这就是"拉伸成品图"永远失败的根因，`StretchBlt` 和 `compose(放大尺寸)` 两条路都是同一个坑。

**规矩**：要缩放，**画布尺寸 = 输出尺寸**，几何在布局阶段就乘好。

### 5. 参数量化的功能，要在做功能之前先参数化
停靠站如果不是先做成"宽度由光标数算出来"，后面加 zoom 就会重复面板的翻车。

**规矩**：任何将来要乘缩放/数量因子的东西，先把几何写成函数，再谈功能。

### 6. 不要吞掉错误
`let _ = SetWindowPos(...)`、`.ok()`、`unwrap_or_else` 让失败完全不可见，
导致"命令被接受但没生效"这种状态查了很久。

**规矩**：至少记进日志；`GetLastError` 为 0 时说明信息无效，要换 windows crate 的 `e.code()`。

### 7. 补丁脚本必须断言，不能静默失败
多次出现"脚本打印成功但替换没匹配上"，最后编译报错才发现。原因包括：
搜索串里的 `\u{2039}` 转义 vs 文件里的字面字符 `‹`、heredoc 把 `\n` 变成真换行。

**规矩**：每个替换后 `assert`，或者跑完立刻 `grep` 复核关键标记。

### 8. 必须用真实鼠标验证，不能用协议模拟
面板开关那次，我用 `{"cmd":"toggle"}` 去"模拟点击"，根本没走窗口过程，
白测一轮还以为功能没做成。改用真鼠标点一次就通了。

**规矩**：UI 必须真点真拖真滚，坐标要**先截图确认**再点（我自己算错坐标好几次）。

### 9. `tsdown` 不做类型检查
`pnpm run build` 报"Build complete"但 `tsc --noEmit` 是红的，差点推上去。

**规矩**：每次提交前单独跑 `tsc --noEmit`。

### 9b. D3D11 三个坑（2026-10-31 小地图 GPU 化踩到）
1. **`Map` 只能用在 DYNAMIC 常量缓冲**：用 `D3D11_USAGE_DEFAULT` 建常量缓冲再 `Map(WRITE_DISCARD)`
   直接 `E_INVALIDARG (0x80070057)`。要 Map 就 DYNAMIC + `CPU_ACCESS_WRITE`，否则用 `UpdateSubresource`。
2. **staging 纹理的 `Map(DO_NOT_WAIT)` 在这个 Intel 驱动上照样阻塞 ~8ms**（1.4MB）。
   本机实测 `map=8172us`，不管有没有 `D3D11_MAP_FLAG_DO_NOT_WAIT`。
   **解法**：`CopyResource` 之后 `End(查询)`，下一帧先 `GetData` 轮询（它不阻塞），
   查到了才 `Map` —— 实测 `8172us → 11us`，同一份代码帧率还从 32fps 升到 44fps。
   教训：`DO_NOT_WAIT` 是"允许驱动不等待"，不是"保证驱动不等待"；要非阻塞必须自己拿查询做栅栏。
3. **WARP 设备 + 真实输出，`DuplicateOutput` 返回 `E_INVALIDARG` 而不是 `DXGI_ERROR_UNSUPPORTED`**。
   只认 UNSUPPORTED 会在某些驱动上一直重试而不降级。判"这台设备抓不了这个输出"要连
   `UNSUPPORTED / NOT_CURRENTLY_AVAILABLE / INVALID_CALL / E_INVALIDARG` 一起认。

### 9c. 先量每一段，再决定优化谁
本轮一开始"readback 6.5ms"是靠 `copy / map / rows` 三段分开计时才定位的：
`copy=3us map=8172us rows=191us` —— 一眼看出瓶颈在 Map，不在拷回内存。
**规矩**：GPU 异步管线的耗时，必须按阶段打点（main.rs 每 2s 打一行 `map stats`）。

### 10. 关键结论以日志为准
`bin/logs/overlay.log`：自动保存、512KB 轮转保留 5 份、`{cmd:"log_export",path}` 可导出。
