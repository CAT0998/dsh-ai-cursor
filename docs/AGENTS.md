# 子代理花名册（复用优先，别乱开新的）

> **没有"归档/删除子代理"的工具**，团队上限 8 个。
> 不活跃的子代理本身不耗资源，所以"归档"的正确做法是：**记录专长 → 按需复用**，
> 而不是重复开新的（会撞上限）。

**用法**：新任务来了，先在这张表里找专长最匹配的，用 `send_message` 唤醒它
（`send_message` 对不活跃成员会启动一轮）。确实没有合适的，再考虑新开。

| 名字 | 专长 | 适合的任务 | 状态 |
|---|---|---|---|
| `panel-window` | 面板窗口化、布局、滚动、resize、命中 | 面板/布局/交互类 | 复用中（T6 面板四项） |
| `freeze-fix` | 主循环、命令分发、卡死排查 | 主循环/协议/性能模式 | 复用中（T8 性能模式） |
| `gpu-minimap` | Windows 图形 API（DXGI/D3D11/Desktop Duplication）、抓屏 | GPU/显示/抓屏/多屏 | 空闲 |
| `tinyskia-probe` | 渲染性能基准、tiny-skia、像素比对 | 渲染选型/基准测量 | 空闲 |
| `panel-redesign` | 面板信息架构、分区拆分、存储设计、宿主端路由 | 面板结构/数据模型 | 空闲 |
| `doc-critic` | 批判性评估、用数据推翻假设 | 方案评审/风险分析 | 空闲 |
| `doc-designer` | 文档形式设计、可机检的结构 | 文档体系/索引设计 | 空闲 |
| `docs-writer` | README/对外文档写作 | 发布/说明文档 | 空闲 |

## 使用规矩
1. **优先复用**，不要为每个任务新开（上限 8，撞了就派不出去）
2. 交付要求写清：改哪些地方、怎么验证、**不要提交 git**（lead 统一提交）
3. 用户明确要求：**验证从简**，小改动编译 + 一次冒烟即可，别让子代理跑全套
4. 每个子代理的报告我要**自己复核关键数字**，不照单全收
